## 5.1 测试方案与用例设计

本章采用六层测试策略，自下而上覆盖数据版本到完整业务链路：

1. **数据版本层**：依据高帅龙 M1 交付包的 manifest 与三张 CSV，校验 frozen 状态、契约版本、sha256 指纹、行数、列名顺序、主键唯一、无孤立引用、ID 格式与值域，共 21 条用例。这一层直接读取真实交付物，结论真实有效。
2. **中英映射层**（2026-11-19 新增）：校验组长提交的职业/技能中文名映射表的条数、ID 一一对应、主键唯一、`name_en` 与正式表一致、生成脚本重跑 SHA 幂等、manifest 元信息与后端接口返回 `name_zh`，共 13 条用例；自检模式因后端未接入而 skip，真实后端模式全部通过。
3. **契约层**：用 Pydantic 模型直接校验 `data_contract.md` 定义的字段，覆盖必填、类型、取值枚举、命名规范，共 23 条用例。这一层不依赖任何队友代码，结论真实有效。
4. **接口层**：用 FastAPI 的 `TestClient` 调用接口，检查 HTTP 状态码、业务 `code`、响应结构，覆盖正常与异常输入，共 13 条用例（详见 5.2、5.4）。
5. **算法与推荐层**：验证 Top-5 数量与排序、匹配分数范围、技能差距分级、发展路径对齐，以及典型画像的推荐合理性，共 15 条用例。2026-11-20 起已接入正式算法 `matcher-v1`（main `611c732`）复测通过；自检阶段的知识库从 M1 真实三表加载（28 职业 / 35 技能 / 492 关联），`importance` 按 A1 口径做 `(IM-1)/4` 归一化。
6. **链路层**：从用户填报到推荐结果、技能差距、发展路径一条走通，共 2 条用例。

用例编号规则：`TC-模块-序号`，模块前缀固定为 DATA / DATAV / MAP / API / EX / ALG / REC / E2E 八类，与附录 C 的用例清单和表 5-1 的覆盖矩阵使用同一套编号。当前共收集 **89 条用例**（数据版本 21 + 中英映射 13 + 契约 23 + 接口/异常 15 + 算法/推荐 15 + 链路 2；接口层 15 条含 2026-11-20 新增的发展树结构 TC-API-05/06）。其中中英映射层为 2026-11-19 新增，来自组长提交的派生参考数据，自检模式因后端未接入而 skip，真实后端模式全部通过。2026-11-20 最新 main 上，89 条全部真实通过。

两条关键契约断言：

- 成功响应必须同时满足 HTTP 200 与业务 `code=200`，且 `data` 内 `recommendations` 与 `development_paths` 均存在；
- 失败响应不得返回 500：等级越界、字段缺失、类型错误应返回 422，且错误信息能定位到具体字段（如 `self_level`、`user_id`）。**后端修复后真实请求返回统一 422 结构 `{code,message,data.errors[{field,message}]}`（非 FastAPI 原生 detail），越界定位到 `profile.skills.0.self_level`，本断言已通过。**

**测试中发现的一处文档冲突**（已记录，待团队处理）：总体 README 第八节把统一响应字段写成 `requestId`（驼峰），而 `data_contract.md` 第 197 行规定统一用 `request_id`（snake_case）。若前端按 README 取值、后端按契约返回，会出现字段读不到的隐性 bug。已新增 `TC-DATA-15` 锁定契约口径（断言字段必须是 `request_id` 而非 `requestId`），并建议由 README 负责人修订该处。详见 `报告_初级/文档一致性核对记录.md`。

**可解释性检查**：每条推荐均返回非空 `recommendation_reasons`，说明匹配分数、已具备技能数、待加强/待验证技能数；TC-REC-04 校验了这一点。`match_score` 为模型内部相对指标，理论区间 [0.000, 1.000]（实测全 0 级 = 0.000、全 4 级 = 1.000），**不是概率，不得表述为匹配度百分比、就业概率或录取概率**。回归基线见 `d4_cases.json`。

**已知局限**（如实写入，答辩时不要回避）：

1. 当前参考算法为技能向量余弦相似度，未使用语义嵌入，同义技能无法自动关联；
2. 知识库为 M1 真实交付的 28 职业 / 35 技能 MVP 子集（IT 与金融分析方向），非 O*NET 全量 1016 职业，跨领域职业不在覆盖范围；
3. 技能粒度偏粗，数据方实测 28 职业平均 Jaccard 相似度 0.665，相似职业之间的推荐区分度有限；
4. `importance` 为原始 IM(1~5)、`required_level` 实际值域 1~3（契约定义 0~4），测试未做"覆盖 0~4 全档位"的断言——这是数据方明确提醒的口径。

以上属于第一阶段的范围边界与数据现实，不是实现缺陷。
