## 四、字段结构与实测统计

**职业表 `occupation_data.csv`**

`O*NET-SOC Code`（职业ID）、`Title`（名称）、`Description`（描述）—— 对应契约 `occupation_id / name / description`。

**技能评分表 `essential_skills.csv` / `transferable_skills.csv`**

| 字段 | 含义 | 对应契约字段 |
|---|---|---|
| `O*NET-SOC Code` | 职业 ID | `occupation_id` |
| `Element ID` | 技能 ID（如 2.B.3.e = Programming） | `skill_id` |
| `Element Name` | 技能名称 | `name` |
| `Scale ID` | `IM`=重要性 / `LV`=等级 | 决定映射到哪个字段 |
| `Data Value` | 评分值 | `importance` 或 `required_level` |
| `N` / `Standard Error` / CI 上下界 | 样本量与统计精度 | 可信度参考 |
| `Recommend Suppress` / `Not Relevant` | 低精度标记 / 无关标记 | 清洗过滤依据 |
| `Date` / `Domain Source` | 更新日期 / 来源 | `source` |

**实测统计**

- `essential_skills.csv`：18,200 行 = 9,100 IM + 9,100 LV；IM 取值 1～5，LV 取值 0～7；**910 个职业两套评分都全**；10 种核心技能。
- `transferable_skills.csv`：45,500 行；25 种可迁移技能（含 Programming、Complex Problem Solving 等）。
- 两类合计约 35 个稳定技能 ID。

## 五、字段映射方案（待算法负责人确认）

| 需求 | O*NET 来源 | 处理方式 |
|---|---|---|
| 职业 ID / 名称 / 描述 | `occupation_data.csv` 三列 | ID 加前缀 `ONET-`；保留 `source=onet`、`source_id=原始SOC码` |
| 技能 ID / 名称 / 分类 | `Element ID` / `Element Name` | ID 前缀 `ONET-`；`category` 用 Essential / Transferable 分组 |
| `importance` | `Scale ID=IM` 的 `Data Value` | 原始 1～5，建议 `(v-1)/4` 归一化到 0～1（**待赵帝臣确认**） |
| `required_level` | `Scale ID=LV` 的 `Data Value` | 原始 0～7，建议 `round(v×4/7)` 到 0～4（**待赵帝臣确认**） |
| 关联唯一性 | 同一 (SOC, Element) 有 IM、LV 两行 | 透视成一行：IM→importance，LV→required_level；缺失一侧留空 |

## 六、风险与注意事项

1. **地域代表性**：O*NET 是美国体系，**不代表中国就业市场**（ADR-003 明确要求保留来源并映射）。匹配分只代表模型内部相对适配指标，不可解释为进入某职业的统计概率。
2. **等级量表不一致**：IM 1～5、LV 0～7，契约要 0～1 和 0～4。映射规则**必须由赵帝臣确认**后固化。
3. **技能粒度**：约 35 种技能偏粗但稳定；若算法需要更细粒度，可从 O*NET Technology Skills 扩充。
4. **统计精度**：`Recommend Suppress=Y` 的记录应过滤或降权，避免低精度评分进入推荐。
5. **许可合规**：CC BY 4.0，`manifest.json` 已记录来源，最终文档需保留署名与链接。
